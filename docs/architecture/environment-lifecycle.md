# 环境生命周期

首页的环境卡片使用原版 DSH Menu、Button、Modal 和 Input，提供复制、重命名、暂停／恢复与删除。复制的内容与边界见 [环境复制](environment-copy.md)。

## 操作行为

| 操作 | 数据和运行行为 |
| --- | --- |
| 重命名 | 更新平台目录中的显示名称；环境 ID、配置与会话保持原有归属。运行中和已暂停环境均可重命名 |
| 暂停 | 停止智能体、终端、Worker JavaScript、定时唤醒、插件构建容器和工作区容器；容器正常停机时先同步文件，持久数据保留 |
| 恢复 | 重新开放环境、会话和文件卷，恢复已保存的提醒唤醒时间。服务按需启动，终端命令与被取消的运行任务需要重新提交 |
| 删除 | 停止运行，清除所属 SessionDO、WorkspaceDO、EnvironmentDO 的用户表与 KV，清理所属 R2 插件产物。输入环境名称确认后执行，无法撤销 |

默认环境承担旧版 API 的缺省路由，可以暂停与重命名，不允许删除。参与进行中复制的源环境和目标环境需要等复制结束后再暂停或删除；失败的副本可重试复制或删除。暂停／恢复／删除尚未完成时，需先完成或重试当前操作。

## 数据归属与恢复

D1 保存租户环境目录、显示名称与生命周期状态；TenantDO 的本地 SQLite 操作日志保存版本号、步骤、资源清单及批次游标。环境内部仍由各自的 DO 管理，无需增加环境配置对 D1 的查询。入口向 TenantDO 查询其内存中的权威目录，避免跨 Worker 的短期缓存继续放行已关闭的环境。

EnvironmentDO 冻结环境服务并返回会话和物理文件卷清单。隐藏的资源登记表同时记录尚未进入可见会话列表的实际资源，避免重现空白会话问题。暂停先停止会话，再停止文件卷；恢复先开放文件卷与会话，再开放环境服务，最后重设提醒 Alarm。每批完成后保存游标，TenantDO Alarm 继续处理下一批。失败保留进度和错误，支持自动重试和首页手动重试，重启后继续。

每个对象保留本地持久状态与操作版本。旧请求的异步继续执行通过 AsyncLocalStorage 携带原有版本，存储代理拒绝过期写入；关闭已有流、取消运行后再清理数据。容器宿主和插件构建宿主同样保存停止标记和版本，防止旧请求重新启动计算实例。

删除后仅保留内部生命周期标记，D1 保留不可复用的环境 ID 与删除状态，不再列入首页及活动环境限额。这阻止延迟请求重新创建已删除的环境。该功能沿用 `harness-v2` 数据布局，无需重置现有数据或新增 D1 迁移。

## API

以下路径均相对 `/v1/tenants/:tenantId/environments`，要求所属登录用户；修改操作沿用同源校验。

| 方法与路径 | 请求与结果 |
| --- | --- |
| `PATCH /:id` | `{ "name": "新名称" }`，返回更新后的环境 |
| `POST /:id/lifecycle` | `{ "action": "suspend" }` 或 `{ "action": "resume" }`，异步操作返回 `202` |
| `DELETE /:id` | 异步删除返回 `202`，已删除时再次删除返回 `200` |
| `GET /:id` | 返回当前进度；完成删除后返回 `410` |

非就绪环境的业务请求返回 `409`，已删除环境返回 `410`，其他租户请求返回 `403`。首页轮询进度，后台处理不依赖页面保持打开。
