## English

Weft moves to upstream **DSH 0.2.2-rc.1** and takes the same version number. 0.2.2 changes several Host contracts incompatibly with 0.2.1, so this release is compatible with DSH 0.2.2-rc.1 only.

- The native runtime, official Web client, Remote ABI and official profile are built from the pinned 0.2.2-rc.1 source.
- Tools run through the official `tool-executor-native` executor; the PTC preset uses `tool-executor-ptc` with a separate Dynamic Worker per program run.
- Schedule follows the 0.2.2 Host-wide API: RRULE timing, `active` / `paused` / `ended` tasks, and `create`, `list`, `view`, `edit`, `history` and `run` by task id. Each Session stores the tasks that deliver to it and the environment aggregates them. Targets that would create a new Session are refused.
- Session images are read from the environment's attachment store by their complete reference, without scanning Session history.
- File writes, edits, deletions and moves no longer require a prior read, matching the official default.
- Since the 0.1.0 release: the `@weft/dsh-superagent` plugin, environment-owned Worker Host plugins, Session turn notifications, the shared outbound connection gateway and local connector carrier protocol 3.

### Compatibility and deployment

Targets upstream **DSH 0.2.2-rc.1** (commit `66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db`). The local connector is independently versioned at **0.5.0** and supports native Hosts **0.2.2-rc.1** only. DSH 0.2.2 requires Node 24.9 or newer. Connector 0.4.0 and earlier accept only 0.2.1 releases: upgrade DSH and the connector together. Existing pairing files are kept.

Sessions created under DSH 0.2.1 keep their history, which stays readable, but they no longer run and cannot be continued. Start new Sessions after upgrading. Official presets are republished for the new runtime. The environment's own presets, including edited official presets, drop the merged `tool-subagent-list-agents` row, map `modelSelectionSettings` to `modelSelection` and `modelDiscovery`, and are republished when they still validate. A preset that does not validate stays unchanged and must be edited before use.

Schedule stores keep their data: version 1 tasks remain readable and are stamped version 2 on their first change. A DSH 0.2.1 runtime cannot open a store after that change, so keep a backup if you may roll back.

The workspace container and plugin builder image tags change. Publish both images from the CI run of this exact commit before deploying the Worker. This release adds no database migration or data reset.

## 简体中文

Weft 升级到上游 **DSH 0.2.2-rc.1**，并采用相同的版本号。0.2.2 有多项 Host 契约与 0.2.1 不兼容，因此本版本只兼容 DSH 0.2.2-rc.1。

- 原生运行时、官方 Web 客户端、Remote ABI 与官方 profile 均由固定的 0.2.2-rc.1 源码构建。
- 工具经官方 `tool-executor-native` 执行器运行；PTC 预设使用 `tool-executor-ptc`，每次程序运行使用独立的 Dynamic Worker。
- Schedule 采用 0.2.2 的 Host 级 API：RRULE 计时，任务状态为 `active` / `paused` / `ended`，按任务 id 执行 `create`、`list`、`view`、`edit`、`history` 与 `run`。每个会话保存投递给自己的任务，由环境汇总；会新建会话的投递目标会被拒绝。
- 会话图片按完整引用从环境附件存储读取，不再扫描会话历史。
- 写入、编辑、删除与移动文件不再要求先读取，与官方默认一致。
- 0.1.0 之后的新增内容：`@weft/dsh-superagent` 插件、环境级 Worker Host 插件、会话回合通知、共享出站长连接网关、本地连接传输协议 3。

### 兼容与部署

适配上游 **DSH 0.2.2-rc.1**（提交 `66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db`）。本地连接插件独立版本为 **0.5.0**，只支持原版 Host **0.2.2-rc.1**。DSH 0.2.2 要求 Node 24.9 及以上。0.4.0 及更早的连接插件只接受 0.2.1，需同时升级 DSH 与连接插件；已有配对文件保留。

DSH 0.2.1 时期创建的会话保留历史且仍可阅读，但不能继续运行。升级后请新建会话。官方预设会以新运行时重新发布。环境自己的预设（含改过的官方预设）会去掉已合并的 `tool-subagent-list-agents` 行，把 `modelSelectionSettings` 改为 `modelSelection` 与 `modelDiscovery`，校验通过后重新发布；校验失败的预设保持原样，需编辑后才能使用。

Schedule 存储保留数据：版本 1 的任务仍可读取，首次修改时写为版本 2。此后 DSH 0.2.1 运行时无法打开该存储，如需回退请先备份。

工作区容器与插件构建镜像的标签均有变化。部署 Worker 前，从本提交通过 CI 的运行中发布两份镜像。本版本不新增数据库迁移，也不重置数据。
