# 使用本地 DSH 环境

本地模式支持 **DSH 0.2.1-rc.2、0.2.1-rc.3、0.2.1-rc.4**。本机运行原版 `dsh web` 或
DeepSeek Harness 桌面 App，安装 `@laciaproject/dsh-local-host` Host 组合包；Weft 提供环境目录、设备配对与出站连接中继。
会话、预设、模型凭据、工作区、Git、终端和插件均由本地 Host 管理。

桌面 App 内置的 Host 与 `dsh web` 是同一个 npm 发布版：它以 `desktop` profile 调用原版 `runProfile`，
在 `127.0.0.1` 的随机端口监听，插件 profile 由 Web 模板初始化。连接插件依赖的 WebServer、浏览器认证与
Client Modules 两者一致，因此无需单独的桌面版本。关闭窗口只是隐藏，Host 和任务继续运行；完全退出或更新重启期间，
Weft 中的环境显示离线，Host 重新启动后自动重连。仅依赖 Electron 私有 IPC 的能力（账号登录窗口、更新提示、原生拖放）
不经过 Weft 中转。

截至 2026-10-28，最新发布版为 `0.2.1-rc.4`。要使用 rc.4，执行 `npm install -g @deepseek-ai/dsh@0.2.1-rc.4`；
桌面 App 按自身渠道更新。
已安装旧连接插件的用户可下载并升级到 **0.2.1**，再升级本地 DSH；
已有配对配置及本地数据可以保留。插件安装器、Host 和中继使用同一份明确的
版本清单，未审查的后续版本会被拒绝。CI 分别安装这两个 npm 原版验证原生
文件、Git、PTY、界面配对和刷新恢复。云端运行时也已升级为 `upstream.lock.json` 固定的 rc.3。

## 部署者配置 Cloudflare Access

保留站点现有的 Access 登录策略。另建一个更具体的 Self-hosted Access
application，仅匹配同一域名的 **`/v1/local-hosts/*`**，使用 Bypass 策略。
不要放行 `/v1/tenants/*`、首页、插件下载或其他接口。检查 Access 的路径匹配
优先级，确保设备端点不会收到登录重定向，而网页入口仍要求用户登录。

这两个设备端点使用应用自身认证，不信任浏览器 Cookie 或自报的用户 ID：

- `POST /v1/local-hosts/:tenant/:environment/pair`：256 bit 配对密钥，10 分钟
  有效且仅可交换一次。返回的设备密钥仅属于该租户与环境。
- `GET /v1/local-hosts/:tenant/:environment/connect`：带设备密钥的 TLS
  WebSocket，校验传输版本与 DSH 版本。拒绝浏览器 Origin。

密钥只以 SHA-256 摘要保存在 TenantDO。登记目录仍在平台 D1；云端不创建该
环境的 Harness、SessionDO 或 WorkspaceDO。连接关闭后，运行中的 HTTP 请求
与网页流会结束；中继不会重放命令。设备连接可重试，浏览器使用原版连接恢复。

Cloudflare 是 TLS 终点，中继会处理传输内容；本版不提供端到端加密。每个
租户最多 64 条网页连接、每个中继实例最多 64 个在途 HTTP 请求，正文分块
32 KiB，文件不会整体读入内存。
0.2.6 使用传输协议 3，中继与插件必须同为协议 3，旧版插件会被判为版本不兼容。
HTTP 正文与原版 Mux 消息都按 32 KiB 分块，每条流最多 16 块未确认（滑动窗口），
中继在浏览器取走一块后才确认，往返延迟不再按块累加。脚本、样式、JSON 等文本响应
在设备连接上以 gzip 传输，由中继还原后交给浏览器。
原版 Mux 完整消息最多 8 MiB，保持每条网页连接的消息顺序；单个设备方向的待发送与重组
缓冲合计最多 16 MiB，单连接排队最多 1024 条消息，允许终端按键等小消息突发。
慢消费者、乱序或超限只关闭
对应网页流，其他标签页继续使用。超时或重连会释放未完成片段，不重放调用。
更大的历史快照仍需要原版分页支持，不承诺无限消息大小。

带内容修订号的 `/plugins/` 和 `/assets/` 成功响应可在浏览器私有缓存中复用，
缓存 URL 包含租户、环境和资源修订号，并按 Cookie 区分；HTML、API、无修订号
资源和失败响应不缓存。首页隐藏时暂停环境轮询，返回前台立即刷新，网络失败退避。

协议 2 每 20 秒发送设备心跳，由 Durable Object 的自动响应处理，不为心跳唤醒
对象。设备失联超过 75 秒后，环境状态或代理请求会将它判为离线并关闭旧连接；
本机恢复网络后自动重连，网页流重新获取原版基线。

## 用户安装

1. 本机先运行 DSH `0.2.1-rc.2`、`0.2.1-rc.3` 或 `0.2.1-rc.4` 的 `dsh web`，或打开同版本的 DeepSeek Harness 桌面 App。
   `0.1.7-rc.2` 等旧版需要先升级：`npm install -g @deepseek-ai/dsh@0.2.1-rc.4`，然后重新启动 DSH。
   在 Weft 首页选择「连接本地 DSH」，输入名称并点击「生成配对码」和「复制配对码」。
2. 在本地原版 DSH 或桌面 App 的「插件」页添加 npm 包 `@laciaproject/dsh-local-host`，
   或执行 `dsh plugin --profile web add @laciaproject/dsh-local-host@0.2.6`。桌面 App 也可在完全退出后执行
   `dsh plugin --profile desktop add @laciaproject/dsh-local-host@0.2.6`（需先打开过一次桌面 App 以初始化 profile）。也可下载
   页面提供的 `.tgz`，以其绝对路径安装。它原生声明 `dsh.bundle.patch`。
   安装完成后点击「立即启用」。已装过旧名 `@weft/dsh-local-host` 的用户，应先移除旧包再安装新包；配对文件保留。
3. 在本机「插件」列表打开「Weft 本地连接」（`@laciaproject/dsh-local-host`）的详情页，直接填写「配对码」并点击「保存并连接」，无需重启。
   「包含的组件」中的配置入口也提供同一表单，无需寻找单独的设置卡片。
   插件自己显示连接状态、重连和停止按钮，版本不兼容时提示升级，授权撤销时
   提示重新配对，网络中断时自动退避重试。经 Weft 打开的该页只显示状态，连接
   管理由本机页面执行。
4. 默认使用回环 HTTP 监听；不要改为公网监听。
   如果启用了本地 HTTPS，应为 Node 配置受信任的本地证书。
5. 回到首页，状态变成可进入后打开本地工作台。

无需下载或手工创建 JSON。连接插件将配置自动保存到本机 `~/.dsh/weft-connection.json`；
已有配置仍可使用，其他位置可通过 `WEFT_LOCAL_HOST_CONFIG` 指定。
配对码具有一次性授权，应保密，不写入 profile；设置响应不包含密钥或配对码。

连接插件自动把配对密钥换成设备密钥，以 `0600` 权限原子写回配置文件。
首次配对后无需每次网页登录。为不同电脑或不同本地 profile 使用不同环境和
配置文件；同一环境的新连接会替换旧连接。

「断开连接」会立即撤销设备密钥和所有活动连接。「重新配对」生成新的一次性
配置，也会撤销旧密钥。移除环境只删除 Weft 登记和授权，保留本地文件与进程。
本机插件页的「停止连接」只停止当前出站连接，保留设备密钥以便重新连接；
Weft 首页的「断开连接」撤销授权，需要重新配对。停止本地 DSH 或关闭本地连接
插件也会停止连接重试。Web 不远程启动已关闭的电脑。

## 插件与版本边界

网页加载本地 Host 生成的完整原版前端、Boot Graph 和客户端插件资源，因此
客户端与 Host 保持同源版本。工作台从环境路径挂载，原版使用相对地址的
`/api/`、`/plugins/`、`/assets/` 路由可以透传。Web 环境与本地环境的数据不会
合并或自动迁移；已有云端环境保持现有行为。

自定义根路径、硬编码站点绝对路径、外部 origin 和客户端 HMR 路由暂不代理。
这类第三方插件需支持挂载路径后接入；安装后的插件和 DSH 升级需重新校验版本。

发布者使用固定仓库、工作流及环境的 npm OIDC 发布，详见 [npm 发布](npm-publishing.md)。
